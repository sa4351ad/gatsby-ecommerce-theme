# سجل التطوير (Changelog)

يوثّق هذا الملف كل مرحلة تطوير في المشروع، مع رقم إصدار لكل مرحلة. يُحدَّث هذا الملف
عند إعلان اكتمال كل مرحلة جديدة.

يتبع المشروع [Semantic Versioning](https://semver.org): `MAJOR.MINOR.PATCH`
— يزيد `MAJOR` عند تغييرات جوهرية في المعمارية أو كسر توافق، `MINOR` عند إضافة
ميزات جديدة، و`PATCH` عند إصلاحات وتحسينات لا تضيف ميزات جديدة.

## [1.0.0] — 2026-08-29 — المرحلة الأولى: النظام الأساسي الكامل

أول نسخة عاملة كاملة من النظام، جاهزة لمراجعة فريق العمل.

### المكوّنات المكتملة
- **المعمارية والتصميم**: `ARCHITECTURE.md` كامل (المخطط، RBAC، منطق التصويت، النموذج الأمني).
- **Backend** (`apps/api`): مصادقة OTP للأعضاء + بريد/كلمة مرور للإداريين، RBAC ديناميكي،
  محرك تصويت كامل (تصويت موزون، نصاب بثلاث طرق احتساب، تصويت سري بإخفاء هوية حقيقي،
  منع تصويت مكرر على مستوى قاعدة البيانات، تغيير الصوت بنمط Append-only، انتخابات بحد
  مقاعد)، استيراد أعضاء من Excel، مزوّدات SMS/Email قابلة للتوسع، تقارير CSV/Excel/PDF،
  سجل تدقيق شامل.
- **Frontend** (`apps/web`): رحلة العضو الكاملة ولوحة تحكم إدارية كاملة (أعضاء، مجموعات،
  اجتماعات، تصويتات، نتائج حية، إعدادات، سجل تدقيق) — واجهة عربية RTL بالكامل.
- **قاعدة البيانات**: مخطط Prisma كامل (~30 جدول)، بيانات تجريبية شاملة.
- **الاختبارات**: 29 اختبارًا آليًا (Vitest + Supertest) تغطي كل المسارات الحساسة أمنيًا
  ومنطقيًا (OTP، منع التصويت المكرر بما فيها التزامن، النتائج الموزونة، النصاب، التحكم
  الزمني، إخفاء الهوية في التصويت السري، RBAC/CSRF).
- **النشر**: Docker Compose جاهز للنشر على أي VPS.

### أخطاء حقيقية اكتُشفت وأُصلحت أثناء التجربة الحية (قبل هذا الإصدار)
هذه أخطاء وُجدت فعليًا أثناء التشغيل الحقيقي (وليس مراجعة كود نظرية)، ما يعني أن هذا
الإصدار مُختبَر عمليًا وليس فقط مبنيًا نظريًا:
1. احتساب مضاعف لأصوات الأعضاء الذين غيّروا تصويتهم (لم يُستبعَد السجل القديم من النتائج).
2. تعارض محتمل في الأرقام المرجعية عند اعتماد أصوات متزامنة (Race Condition).
3. بصمة تكامل التصويت (Integrity Hash) لم تكن تغطي كل حقول الإجابة.
4. تسريب بيانات أعضاء آخرين (هوية/جوال) عبر واجهة تفاصيل التصويت لعضو غير مخوَّل.
5. إمكانية استبدال عضو لصورة عضو آخر (IDOR) في رفع الصور الشخصية.
6. حزم `@ga/shared`/`@ga/db` كانت تُشحن كملفات TypeScript خام بلا بناء — يعمل في التطوير
   عبر `tsx` لكن ينهار عند التشغيل الفعلي في الإنتاج (`node dist/server.js`) أو حتى في
   التطوير المحلي الطازج (بعد `pnpm install` فقط، بلا بناء يدوي مسبق).
7. جلسة تسجيل دخول الإدارة: صفحة الدخول ولوحة الإدارة تشتركان في نفس الحاوية (Layout) في
   Next.js التي لا تُعاد من جديد عند الانتقال بينهما، فكانت بيانات الجلسة المحلية تبقى
   قديمة (غير مسجَّل دخول) رغم نجاح تسجيل الدخول فعليًا، فيُعاد المستخدم لصفحة الدخول.
8. عند نشر الواجهة والـ API على نطاقين منفصلين تمامًا (كما في تجربة الاستضافة السحابية)،
   كانت كوكيز الجلسة تُعامَل كـ"طرف ثالث" فتُحجب في المتصفحات الحديثة — أُصلح جذريًا
   بجعل خادم الواجهة يمرّر طلبات `/api/*` داخليًا للـ API (Reverse Proxy) بدل اتصال
   المتصفح المباشر بنطاق مختلف.

### حدود معروفة (خارج نطاق هذه المرحلة، راجع `README.md` §11)
- إنشاء إداريين جدد يتم حاليًا عبر سكربت وليس واجهة رسومية.
- واجهة اختيار أعضاء محدَّدين يدويًا لتصويت `SELECTED` غير مبنية بعد (الـ API يدعمها).
- تصويت الـ Ranking/Percentage مُنفَّذ في المحرك لكن غير مبني في واجهة الإنشاء بعد.
- التصويت بالوكالة (Proxy Voting) والتوقيع الإلكتروني المتقدم وWhatsApp وMulti-Tenant:
  البنية جاهزة للتوسع دون إعادة تصميم قاعدة البيانات، لكن غير مُنفَّذة.
